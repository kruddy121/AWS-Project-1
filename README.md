# Real-Time Security Event Streaming Pipeline

This project is a real-time data streaming and security analytics pipeline built with AWS and Python. It simulates security-related user activity, streams the events through Amazon Kinesis, processes them with AWS Lambda, stores processed event data in Amazon S3, analyzes the data with Amazon Athena, and visualizes the results in Amazon Quick.

## Project Goals

The goal of this project is to build a simple cloud-based real-time security event pipeline that can:

- Generate simulated security events
- Stream events in real time
- Process events automatically
- Store processed event data
- Query stored data using SQL
- Visualize security activity through a dashboard
- Provide a foundation for future detection rules and automated alerts

## Architecture

```text
Python Producer
      ↓
Amazon Kinesis Data Streams
      ↓
AWS Lambda
      ↓
Amazon S3
      ↓
Amazon Athena
      ↓
Amazon Quick
```

## Data Flow

1. `producer.py` generates simulated security events.
2. Each event is sent to Amazon Kinesis Data Streams.
3. Kinesis triggers the AWS Lambda function.
4. Lambda decodes the incoming Kinesis payload from Base64.
5. Lambda converts the event back into JSON.
6. The processed event is stored in Amazon S3.
7. Amazon Athena queries the event data stored in S3.
8. An Athena view converts event timestamps into a dashboard-friendly datetime format.
9. Amazon Quick uses Athena as its data source to visualize the security data.

## AWS Services Used

### Amazon Kinesis Data Streams

Amazon Kinesis receives simulated security events generated by the Python producer in real time.

### AWS Lambda

AWS Lambda processes incoming Kinesis records. The Lambda function decodes each Kinesis payload, converts it back into JSON, and stores the processed event in Amazon S3.

### Amazon S3

Amazon S3 stores processed security events for long-term storage and analytics.

The current event folder structure is:

```text
security-events/
└── YYYY-MM-DD/
    ├── event-HH-MM-SS.json
    ├── event-HH-MM-SS.json
    └── ...
```

Athena query results are also stored in the S3 bucket.

### Amazon Athena

Amazon Athena allows SQL queries to be run directly against the security event data stored in S3.

The project currently uses:

- Database: `streaming_security`
- Table: `security_events`
- Dashboard view: `security_events_dashboard`

The dashboard view converts the original timestamp field into a datetime field called `event_time` so that the data can be grouped properly in dashboard visualizations.

### Amazon Quick

Amazon Quick is used to visualize Athena query data and create the security monitoring dashboard.

### Amazon CloudWatch

Amazon CloudWatch is used to monitor Lambda executions and review logs for troubleshooting the streaming pipeline.

### AWS IAM

AWS IAM manages permissions for the AWS CLI user and Lambda execution role.

## Event Data

The Python producer generates simulated security events with fields such as:

```json
{
  "timestamp": "2026-10-01T01:24:00.470895+00:00",
  "user_id": "user_104",
  "ip_address": "192.168.7.83",
  "event_type": "failed_login",
  "device": "Windows",
  "location": "Maryland",
  "risk_level": "medium"
}
```

## Event Types

The producer currently simulates:

- `login_success`
- `logout`
- `failed_login`
- `password_reset`
- `account_locked`

The event types are weighted so that normal activity occurs more frequently than higher-risk security events.

## Risk Levels

| Event Type | Risk Level |
| --- | --- |
| `login_success` | Low |
| `logout` | Low |
| `failed_login` | Medium |
| `password_reset` | Medium |
| `account_locked` | High |

## Dashboard

The project includes a real-time security monitoring dashboard built with Amazon Quick and connected to Athena.

The dashboard currently includes:

- Total Security Events
- High Risk Events
- Events by Type
- Failed Logins by User
- Events by Location
- Events by Risk Level
- Security Events Over Time by Risk Level

The `security_events_dashboard` Athena view is used to provide a properly formatted `event_time` field for time-based visualizations.

## Running the Producer

First, verify that AWS CLI authentication is working:

```bash
aws sts get-caller-identity
```

Verify that the AWS region is set to:

```text
us-east-1
```

Check the current region with:

```bash
aws configure get region
```

Then start the producer:

```bash
python3 producer.py
```

The producer generates and sends a new simulated security event approximately every five seconds.

Stop the producer with:

```text
Control + C
```

## Example Athena Queries

### Count Events by Type

```sql
SELECT event_type, COUNT(*) AS total_events
FROM security_events
GROUP BY event_type
ORDER BY total_events DESC;
```

### Count Events by Risk Level

```sql
SELECT risk_level, COUNT(*) AS total_events
FROM security_events
GROUP BY risk_level
ORDER BY total_events DESC;
```

### Find Users With the Most Failed Login Attempts

```sql
SELECT user_id, COUNT(*) AS failed_logins
FROM security_events
WHERE event_type = 'failed_login'
GROUP BY user_id
ORDER BY failed_logins DESC;
```

### Analyze Events by Location

```sql
SELECT location, COUNT(*) AS total_events
FROM security_events
GROUP BY location
ORDER BY total_events DESC;
```

### Query Dashboard Event Times

```sql
SELECT event_time, event_type, risk_level
FROM security_events_dashboard
ORDER BY event_time DESC
LIMIT 20;
```

## Security

AWS credentials should never be stored directly in project files.

Do not include:

- AWS access keys
- AWS secret access keys
- Session tokens
- Passwords
- Private API keys
- `.env` file contents

AWS credentials should remain configured locally through the AWS CLI.

The `.gitignore` file should include:

```gitignore
__pycache__/
*.pyc

.env
.env.*

.venv/
venv/

.DS_Store

*.pem
*.key

.aws/
```
